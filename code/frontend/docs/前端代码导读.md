## 1. 30 秒理解整个前端

这是一个 **CS2（反恐精英）虚拟选手股票交易模拟器** 的前端界面：市场里 16 名选手（8 队各 2 人）各有股价，
用户可以用虚拟币买入/卖出，看自己的持仓盈亏和交易流水，还能看到 AI 给出的买/卖/持有建议。

技术栈只有三样，全是官方方案，没有 UI 组件库、没有图表库、没有状态管理库：

| 工具                 | 版本                                             | 在这里负责什么                           |
| -------------------- | ------------------------------------------------ | ---------------------------------------- |
| Vue 3（`^3.5`）      | 视图框架，本项目用组合式 API（`<script setup>`） | 把数据变成界面，数据变了界面自动更新     |
| Vue Router（`^5.3`） | 官方路由                                         | 地址栏 URL 和页面的对应关系、登录拦截    |
| Vite（`^8.2`）       | 官方构建工具                                     | 本地开发服务器 + 打包成 `dist/` 静态文件 |

前端**本身不产生任何业务结论**：价格怎么算、盈亏多少、AI 建议说什么，全部由后端接口给；
前端只负责"取数据 → 摆到界面上 → 把用户的点击转成请求"。这也是本项目反复强调的铁律。

界面分两层：

- `App.vue` 是外壳（侧栏导航 + 账户卡片 + 后端连接状态 + 内容区出口）；
- `src/views/` 下 5 个文件是内容区里的 5 个页面。

## 3. 分层：为什么代码要这么拆

从上到下只允许"上层调下层"，反过来不行：

```text
浏览器 / index.html
   └── main.ts            ← 启动
         └── App.vue      ← 外壳（侧栏、导航）
               └── views/  ← 页面：组织数据、组织布局
                     ├── components/  ← 可复用小块：图表、交易面板、三态提示
                     ├── composables/ ← 跨页面共享的状态与逻辑
                     └── api/         ← 所有 HTTP 调用
                           └── mock/  ← 假后端（开发兜底）
```

带来的实际好处：

- 后端接口字段改名 → 只改 `api/types.ts` + `api/index.ts`，页面几乎不动；
- 想换成假数据演示 → 只改 `.env` 里一个开关，页面代码一行不改；
- 想把登录接上后端 → 只重写 `useAuth.ts` 里的 `register/login/logout`，`AuthView.vue` 不用动。

## 4. 数据的两次旅程（跟着这两条线读代码最省力）

### 4.1 打开市场页看到了什么

```text
① 用户访问 /
② router/index.ts 匹配到 MarketView.vue（这条是静态 import，首屏必带）
③ App.vue 的 <RouterView> 渲染出 MarketView
④ MarketView 的 onMounted(load) 触发：
     loading = true                         → 模板显示骨架屏
     checkBackendHealth()                   → useBackendHealth: GET /api/health → 侧栏圆点变色
     api.listPlayers()                      → api/index.ts: request('/api/players')
        └─ client.ts: fetch( VITE_API_BASE_URL + '/api/players' )
             成功 → 把 JSON 返回（类型是 PlayerSummary[]）
             失败 → 抛 ApiError(中文 message, code, status)
     成功 → players.value = 数据，updatedAt = 当前时间   → v-for 画出 8 张卡片
     失败 → error.value = err.message                    → ErrorState 显示中文提示 + 重试
     finally → loading.value = false                     → 撤掉骨架屏
⑤ 用户输入搜索词 → keyword 变 → computed(filtered) 重算 → 列表自动更新（不发请求）
```

关键点：只有 `.value` 被重新赋值的那些 `ref` 会让界面自动更新，这是 Vue 响应式的核心。

### 4.2 在详情页点"买入"

```text
① TradePanel.vue（子组件）本地校验：数量是正整数、≤50，暂停交易直接拦截
② api.buy(player_id, quantity) → POST /api/trades/buy，body { player_id, quantity }
③ 成功：res = { success, message, balance, price, trade_id, ... }
     - 面板立刻显示后端那句中文 message（绿色横幅）
     - emit('traded', res) 通知父页面 —— 子组件不直接改父页面的数据
④ PlayerDetailView 收到 traded：
     loadCore(silent=true)  → 重新拉 详情 + 价格历史 + 持仓（"静默刷新"：不清空、不闪骨架屏）
     loadAnalysis()         → 重新问 AI
     refreshAccount()       → 侧栏余额立刻更新（用的就是后端返回后的数据库真值）
⑤ 失败（余额不足 / 持仓不足 / 超上限 / 暂停交易）：
     红色横幅显示后端 message，输入不清空，用户改数量即可再点一次
     —— 代码里绝不自动重试：重试就变成第二笔真实交易
```

一句话总结：**前端永远不自己算钱**。所有金额、盈亏、涨跌幅、成交结果都以后端为准，前端的计算只为体验（例如"约需金额"预估）。

## 5. Vue / TypeScript 写法小抄（看到不懂的符号就来这查）

| 写法                                  | 意思                                                                                         | 本项目的例子                     |
| ------------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------- |
| `.vue` 文件（SFC）                    | 一个文件三段：`<script setup>` 逻辑、`<template>` 结构、`<style scoped>` 样式                | 全部 views / components          |
| `<script setup lang="ts">`            | 编译期宏：这里的顶层变量自动暴露给模板，不用手写 `export default`                            | 所有组件顶部                     |
| `ref(x)`                              | 包一个"会变的数据"；脚本里读写要加 `.value`，模板里自动解包                                  | `const players = ref([])`        |
| `reactive({...})`                     | 一次声明一组会变的字段（表单常用）                                                           | `AuthView` 的 `loginForm`        |
| `computed(fn)`                        | 由别的响应式数据**推导**出来的只读值，依赖变了自动重算                                       | `MarketView` 的 `filtered`       |
| `watch(src, cb)`                      | 某个值变化时执行副作用                                                                       | `App.vue` 换页自动收起导航抽屉   |
| `onMounted(fn)`                       | 组件渲染到页面之后执行——"进页面就加载数据"写在这                                             | 每个页面 `onMounted(load)`       |
| `v-if / v-else-if / v-else`           | 条件渲染（只有一份会存在 DOM 里）                                                            | 加载/错误/空/正常 四选一         |
| `v-for="p in list" :key="p.id"`       | 列表渲染，`:key` 让 Vue 认出每一行是谁                                                       | 市场卡片、持仓表、流水表         |
| `v-model="x"`                         | 双向绑定：输入改了 `x`，`x` 改了输入也跟着变                                                 | 搜索框、数量输入框               |
| `v-model.number`                      | 同上，但把字符串转成数字                                                                     | `TradePanel` 的 quantity         |
| `:disabled="x"` / `:class="[…]"`      | 冒号 = 把属性值当 JS 表达式计算                                                              | 到处都是                         |
| `@click="fn"`                         | 事件监听（`on` 的缩写）                                                                      | 刷新、买入、卖出                 |
| `defineProps`                         | 父传子的只读参数                                                                             | `TradePanel` 的 `player`、`held` |
| `defineEmits` / `emit('traded', res)` | 子通知父"发生了件事"，父在标签上写 `@traded="…"`                                             | 交易成功回调                     |
| `<slot />`                            | 内容口子，父组件往里塞什么就显示什么（具名口子 `<slot name="meta">`）                        | `CollapsibleCard`、`EmptyState`  |
| `composable（useXxx.ts）`             | 把"状态 + 逻辑"抽成函数/模块，多个页面共用同一份数据                                         | `useAccount`、`useAuth`          |
| 模块级 `ref`                          | `ref` 写在函数外：模块只执行一次，所以所有 import 者共享同一个状态 —— 本项目的"穷人版 Pinia" | `useAccount.ts` 顶部             |
| `readonly(x)`                         | 导出只读，防止别的文件直接乱改共享状态                                                       | `useAccount()` 返回值            |
| `<RouterView>` / `<RouterLink>`       | 页面出口 / 不刷新的站内跳转链接（`<a>` 会整页重载，别用）                                    | `App.vue`                        |
| `import.meta.env.VITE_XXX`            | 读构建时注入的环境变量（来源：`.env.local` / 部署平台变量）                                  | `api/client.ts`                  |
| `interface` / `type`                  | 只描述数据形状，编译后消失；用来让编辑器报错而不是运行时白屏                                 | `api/types.ts`                   |
| `Promise.all([...])`                  | 并发发多个请求，全部回来再往下走                                                             | 详情页 `loadCore`                |
| `?.` / `??`                           | 取不到就给默认值，避免 undefined 崩页面                                                      | `held`、`updatedAt`              |
| `vitest` 的 `describe/it/expect`      | 一组用例 / 一条断言 / 期望值                                                                 | `__tests__/` 全部                |
| `vi.mock` / `vi.hoisted`              | 把某个模块换成可控假货（假接口、慢响应）                                                     | `PlayerDetailView.spec.ts`       |
| `@vue/test-utils` 的 `mount`          | 在假浏览器（jsdom）里渲染组件并检查 DOM                                                      | `PriceChart.spec.ts`             |

### 5.1 三个页面级"套路"，看懂一个就懂全部数据页

```ts
// ① 状态：四件套
const data = ref<T[]>([]) // 数据
const loading = ref(true) // 是否在等
const error = ref<string | null>(null) // 中文错误文案
const updatedAt = ref('') // 这次数据是什么时候拉的

// ② 动作：一次 load 走完全流程
async function load() {
  loading.value = true
  error.value = null
  checkBackendHealth() // 顺带刷新侧栏连接徽标
  try {
    data.value = await api.xxx()
    updatedAt.value = new Date().toLocaleTimeString()
  } catch (err) {
    error.value = err instanceof ApiError ? err.message : '加载失败'
  } finally {
    loading.value = false
  }
}

// ③ 模板：状态四选一（顺序很重要：loading → error → 空 → 正常）
```

```html
<LoadingState v-if="loading" />
<ErrorState v-else-if="error" :message="error" @retry="load" />
<EmptyState v-else-if="data.length === 0"
  >去 <RouterLink to="/">市场</RouterLink> 看看。</EmptyState
>
<table v-else>
  …
</table>
```

| **涨红跌绿**                                    | 国内行情习惯；`--up` 是红、`--down` 是绿，看代码时别按直觉反过来理解                                  |

## 7. 配置文件都在管什么

### 7.1 `package.json` 的 scripts（在 `code/frontend` 目录下执行）

| `npm run dev`        | 开本地开发服务器，默认 http://localhost:5173，改代码即时热更新 | 日常开发                   |
| `npm run build`      | 先类型检查再打包，产物在 `dist/`                               | 部署前                     |
| `npm run preview`    | 本地起一个服务器预览 `dist/` 产物                              | 验证打包结果               |
| `npm run type-check` | 只做 TypeScript 类型检查（`vue-tsc`），不改文件                | 提交前确认类型没问题       |
| `npm run lint`       | oxlint + ESLint 检查并自动修                                   | 提交前                     |
| `npm run format`     | Prettier 统一排版 src/                                         | 觉得代码乱时               |
| `npm run test:unit`  | 跑 Vitest 单元测试                                             | 改完逻辑验证行为           |

### 7.2 `.env` 三兄弟（只有 `VITE_` 开头的能进前端代码）

| 文件              | 是否入库                 | 作用                                                                     |
| ----------------- | ------------------------ | ------------------------------------------------------------------------ |
| `.env.example`    | 入库                     | 模板，写明需要哪两个变量                                                 |
| `.env.local`      | **不入库**（.gitignore） | 你本机实际的后端地址；新克隆后要手动 `Copy-Item .env.example .env.local` |
| `.env.production` | 入库                     | 线上构建时用的 Render 后端地址；部署平台上的同名变量优先级更高           |

两个变量：`VITE_API_BASE_URL`（后端地址，没配就报"未配置后端地址"）、
`VITE_USE_MOCK`（`true` = 用假后端内存数据，联调/上线必须 `false`）。

### 7.3 `tsconfig` 四件套（Project References，各管一片代码）

| 文件                   | 管谁                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tsconfig.json`        | 总入口，只写 `references` 指向下面三个                                                                                                                                                       |
| `tsconfig.app.json`    | 浏览器里跑的代码（`src/**`、`env.d.ts`）。这里开了 `noUncheckedIndexedAccess`（数组/对象下标取值必须处理 undefined，`api/index.ts` 里那些 `as` 断言就是为它写的），也定义了 `@` → `src` 别名 |
| `tsconfig.node.json`   | 在 Node 里跑的配置脚本（`vite.config.ts` 等）                                                                                                                                                |
| `tsconfig.vitest.json` | 测试代码（`__tests__/**`）                                                                                                                                                                   |

### 7.4 质量工具三者分工

- `vite` 负责跑起来 / 打包；
- `oxlint`(`.oxlintrc.json`) 快速找真 bug（未使用变量、明显错误）；
- `eslint`(`eslint.config.ts`) 做 Vue/TS 规则检查；
- `prettier`(`.prettierrc.json`) 只管排版（缩进、引号、换行）。
  所以 `lint` 之后 `format`，两边规则不冲突（`eslint-config-prettier` 就是专门让 ESLint 给排版让路的）。

## 8. 常见任务怎么做

**加一个新页面**（例如 /ranking 排行榜）

1. `src/views/RankingView.vue` 复制 `TradesView.vue`（最简单的四态模板）改内容；
2. `src/router/index.ts` 的 routes 里加一条 `{ path: '/ranking', component: () => import('../views/RankingView.vue') }`；
3. `src/App.vue` 侧栏 `<nav>` 里加一个 `<RouterLink to="/ranking">`（窄屏抽屉同一份导航，会自动带上）；
4. 若要登录才能看，什么都不用改——守卫默认拦截非 `meta.public` 的路由。

**接一个新接口**

1. `src/api/types.ts` 加响应类型（字段照抄后端 JSON，snake_case，不要改成驼峰）；
2. `src/api/index.ts` 加函数 `getXxx: () => request<Xxx>('/api/xxx')`；
3. `src/mock/players.ts` 里加同名假数据函数，并在 `api/index.ts` 的分支里接上 `USE_MOCK ? fromMock(…) : request(…)`；
4. 页面里 `await api.getXxx()`，按第 5.1 节套路处理 loading/error。

**改主题色**：只改 `src/assets/main.css` 里 `:root` 的变量（`--accent`、`--up`、`--down` …）。

**后端没起也要演示**：`.env.local` 写 `VITE_USE_MOCK=true`，重启 `npm run dev`，
界面数据来自 `src/mock/players.ts`（刷新会重置，属正常现象）。

**想去掉登录页这道门槛**：删 `src/router/index.ts` 里的 `router.beforeEach` 即可，界面和账号态互不牵连。

## 9. 排错速查

| 现象                               | 原因                                                               | 处理                                                                   |
| ---------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 页面显示"未配置后端地址…"          | 没有 `.env.local`，或里面 `VITE_API_BASE_URL` 为空                 | `Copy-Item .env.example .env.local` 后重启 dev                         |
| 页面显示"无法连接后端服务…"        | 后端没起 / 地址端口写错 / 跨域被拒                                 | 先 `curl http://127.0.0.1:8000/api/health` 确认后端活着，再核对地址    |
| 侧栏圆点是"后端未连接"，但列表正常 | 徽标只反映 `/api/health` 最近一次结果                              | 点页面"刷新"会顺带复检                                                 |
| 访问 `/market` 白屏（线上）        | 静态站 rewrite 把未知路径都返回 `index.html`，路由没这条会静默空白 | 已由 `router/index.ts` 的 `/market → /` 重定向 + 兜底路由解决，别删    |
| 买入成功但余额没变                 | 交易后没刷新账户                                                   | 检查父页面有没有在 `@traded` 里调 `refreshAccount()`                   |
| 数字和后端差一分                   | 前端自己算了钱                                                     | 违反铁律：金额/涨跌幅一律用后端字段，前端只格式化（`utils/format.ts`） |
| 详情切换选手时旧数据闪现           | 请求竞态                                                           | 保留 `requestToken` 机制（`PlayerDetailView.loadCore`），别去掉        |
| `npm run dev` 端口不是 5173        | 本机端口占用，Vite 自动换端口                                      | 以后端 CORS 白名单为准，把新端口加进去                                 |
| 测试里 `crypto.subtle` 报错        | jsdom 没有 WebCrypto                                               | `useAuth.digest()` 已降级 FNV-1a（仅测试环境，线上是真 SHA-256）       |
