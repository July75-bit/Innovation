# 智能体能力矩阵与答辩演示脚本（第 8 轮）

> 负责人：B（接口/落库） ｜ 配合：D（AI 口径与评测）、A（展示）
> 目的：把"智能体在这个项目里做了什么"从**一句建议卡**，扩成**贯穿主流程的 8 个可演示能力**。
> 所有能力都遵守同一条红线：**只读业务数据、不碰钱**（唯一写入是审计表）。

## 1. 能力矩阵（新增 8 个接口）

| # | 能力 | 接口 | 智能体在做什么 | 契约 |
| --- | --- | --- | --- | --- |
| 1 | **决策卡** | `GET /api/agent/decision/{id}` | 建议 + 建议仓位 + 参考止损 + 置信度 + 逐条依据（按余额/上限/风险预算算） | §4.18 |
| 2 | **今日简报** | `GET /api/agent/brief` | 一进首页就有 3 条要点 + 一句总述（缓存 10 分钟，省 token） | §4.19 |
| 3 | **人在环** | `POST /api/agent/decisions` | 记录"采纳/忽略"；采纳率可查 | §4.20 |
| 4 | **审计** | `GET /api/agent/traces` | 每次调用的模式/来源/耗时/降级原因，可回溯 | §4.21 |
| 5 | **多角色协作** | `GET /api/agent/panel/{id}` | 分析师 → 风控 → 交易员三段纪要，冲突点写明 | §4.22 |
| 6 | **叙事归因** | `GET /api/agent/narrative/{id}` | 把规则 reason 扩写成 2–3 句因果解释（按点缓存） | §4.23 |
| 7 | **工具调用** | `GET /api/agent/tools/{id}` | 模型自己调 3 个只读工具（查价格/查账户/算仓位）再回答 | §4.24 |
| 8 | **定时巡检** | Render cron `0 * * * *` | 智能体每小时自己上班：扫波动、标关注、刷新简报 | `scripts/agent_patrol.py` |

## 2. 与"不碰钱"的关系（答辩必说）

| 设计 | 证据 |
| --- | --- |
| 智能体没有交易权限 | 8 个接口全部只读业务表；下单仍走 `/api/trades/buy|sell` |
| 唯一写入是审计表 | `agent_traces` / `decision_logs` / `price_narratives`，都不影响余额/持仓/流水 |
| 采纳也不等于下单 | `POST /api/agent/decisions` 只写一行记录，前端仍要用户点"买入" |
| 模型不可用一律 200 | 8 个接口都有 `rule_fallback` 路径（有测试守住） |

## 3. 演示顺序（约 3 分钟，可插在详情页那段之后）

1. **首页**：指顶部"智能体简报"→"这是模型每小时/每次刷新生成的 3 条要点"；
2. **详情页**：指 AI 卡下方的决策区块 →"不只说 BUY，还给 12 股、止损 108.4、置信度 72%，并且说明按你 5000 余额算的"；
3. **点"采纳这条建议"** →"记录到人在环表，但**不会自动下单**——下单仍要用户自己点"；
4. （可选）`GET /api/agent/panel/1` →"三个角色分别说了什么，风控和交易员的分歧在哪"；
5. （可选）`GET /api/agent/traces?limit=5` →"每次调用都有审计行：谁调的、多久、有没有降级"。

## 5. 模型对比（一句话讲清"AI 不是摆设"）

| 同一选手（ZywOo） | 规则版 | 模型版（DeepSeek） |
| --- | --- | --- |
| 动作 | HOLD | HOLD |
| 风险 | LOW | **HIGH** |
| 理由 | 模板句（得分/信号） | 自然语言，引用价格、趋势、评分 |

> 话术："规则版按阈值给 LOW，模型看完历史和评分给 HIGH 并说明理由——**两者共用同一 6 字段契约**，前端只按 `source` 区分展示。"

## 7. "智能体占比"的变化（可量化，答辩可直接念）

| 维度 | 改动前 | 改动后 |
| --- | --- | --- |
| 智能体代码量 | `ai/` 828 行 + `api/ai.py` 113 行 ≈ **941 行** | `ai/` **1249 行** + `api/agent.py` **514 行** + `models/agent.py` ≈ **1850 行** |
| 后端代码占比 | ≈ 21% | ≈ **38%** |
| 智能体接口数 | **1 个**（`GET /api/analysis/{id}`） | **9 个**（+决策卡/简报/审计/人在环/统计/多角色/叙事/工具） |
| 触发时机 | 只有打开详情页 | 首页简报（进站即有）+ 详情决策卡 + **cron 每小时自跑** |
| 是否进入交易闭环 | 否（只是展示） | 是（决策卡给仓位、人来点采纳、**采纳有记录可审计**） |
| 审计 | 只有日志文件 | `agent_traces` 表 + `GET /api/agent/traces` 可查 |
| 事后统计 | 无 | 采纳率（`GET /api/agent/decisions/stats`） |

> 一句话："智能体从**详情页的一张卡**，变成**贯穿首页、决策、审计、定时巡检**的一条链；
> 但始终不碰钱——这是设计，不是限制。"

## 8. 已知边界（实事求是）

| 项 | 现状 |
| --- | --- |
| 置信度 | 启发式（来源×评分×波动），**不是概率校准**，文档与响应都写明了 |
| 多角色协作 | 三次串行调用，最坏 3×超时；任一失败整份回落规则版 |
| 摘要/归因 | 有缓存（简报 10 分钟、叙事按价格点），避免重复烧 token |
| 定时巡检 | 免费实例会休眠，cron 触发时后端需冷启动（约 49s），首次可能超时→下次成功；脚本退出码会如实反映 |
