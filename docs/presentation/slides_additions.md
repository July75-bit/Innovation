# 01C 产品定义：我们在做什么

**一句话定义（标准模板）**

> 对于 **关注 CS2 职业选手表现、又想体验数据分析与虚拟交易的观众**，
> 他们希望知道**选手的表现如何变成价格**、并亲手验证自己的判断；
> **PlayerStock** 是一个 **以 CS2 职业选手为标的的虚拟股交易模拟平台**，
> 它能够**把比赛表现转成可解释的价格变动**，提供行情、买卖、持仓、历史走势与 AI 分析建议；
> 不同于**只给结果的赛事资讯站**和**只交易金融标的的模拟盘**，
> 我们的产品**把"选手表现 → 价格 → 你的判断"这条因果链显式做出来了**。

<div class="grid grid-cols-2 gap-8 pt-4">

<div>

**一条用户故事（业务语言，非技术语言）**

> 作为一个**关注 CS2 赛事的观众**，
> 我想在看完一场比赛后**马上买入我认为被低估的选手**，
> 以便于**验证我的判断是不是比解说更早**。

</div>

<div>

**形态与边界**

- 形态：**Web 网页应用**（桌面优先，≤720px 响应式适配）
- 规模：8 名选手、单账户 5000 虚拟币、单选手持仓上限 50 股
- 边界：**不充值、不提现、不兑换、不给赔率、不自动交易**

</div>

</div>

<div class="pt-2 text-xs opacity-60">

不做清单的来源：`docs/requirements/problem_definition.md`（范围冻结点，第 3 天生效）

</div>

# 01D 产品设计原则：四条自我约束

<div class="text-sm opacity-70 pb-2">

不是抄教科书，是**每条原则都能指到我们做过的一个决定**。

</div>

| 原则 | 我们怎么用它 | 落点（可核查） |
| --- | --- | --- |
| **需求原则**：先解决真痛点，再加信息 | 只做"看得懂 + 能验证"两件事，砍掉注册、充值、多用户、撮合盘口 | `problem_definition.md` 的"不做什么"清单 |
| **收敛与优化**：让选择项收敛，而不是发散 | 定价只用一条公式、五个参数；AI 只输出六个字段，不给"价格区间" | `pricing_model.md` §2、`api_contract.md` §4.10 |
| **继承与效益**：复用成熟方案，不重复造轮子 | 不写图表库（自绘 SVG）、不写 ORM、不写鉴权，全部用现成件 | `architecture.md` §4.1 选型论证 |
| **定量与简化**：能被量化的才叫验收 | 每条需求都有可跑的数字：137 条测试、91% 覆盖率、单次涨跌 ≤ 20% | `test_report.md`、`CodeReview.md` §3 |
| **审核原则**：先机器、后人 | CI 三 job 卡门禁；评审看设计而不是看格式 | `CodeReview.md` §4、`docs/reviews/` |
