01 我们解决的问题

用户痛点

  • 想"体验交易"，但真实市场门槛高、风险真实
  • 赛事数据分散，涨跌没有解释，只能看热闹
  • 现有模拟盘标的是公司财报，不是自己关心的选手

目标用户

  • CS2 观众 / 校园赛参与者
  • 想验证"我对选手状态的判断准不准"

我们给的答案

  • 16 名真实 CS2 选手、8 支战队各 2 人（身份公开，价格与评分为模拟数据）
  • 每一分钱变化都能回答"为什么"

01C 产品定义：我们在做什么

对于 关注 CS2 选手表现、又想体验数据分析与虚拟交易的观众，
他们希望知道选手表现如何变成价格、并亲手验证自己的判断；
PlayerStock 是一个以 CS2 职业选手为标的的虚拟股交易模拟平台，
它能把比赛表现转成可解释的价格变动，提供行情、买卖、持仓、走势与 AI 建议；
不同于只给结果的赛事资讯站和只交易金融标的的模拟盘， 我们把"选手表现 → 价格 → 你的判断"这条因果链显式做出来。

一条用户故事（业务语言）

作为一个关注 CS2 赛事的观众，我想在看完一场比赛后马上买入我认为被低估的选手，以便于验证我的判断是不是比解说更早。

形态与边界

  • 形态：Web 网页应用（桌面优先，≤960px 响应式）
  • 规模：16 名选手 / 5000 虚拟币 / 单选手上限 50 股
  • 账号：demo 免登录；可注册私人账号（口令加盐散列、令牌可撤销）
  • 边界：不充值、不提现、不兑换、不给赔率、不自动交易

不做清单来源：docs/requirements/problem_definition.md（第 3 天范围冻结）· 7 条用户故事均带 Given-When-Then

做了刻意不做（及原因）

05 交易正确性：不靠"先查后写"

问题

先 SELECT 判断余额、再 UPDATE 扣款 → 两条并发请求同时通过判断 → 超卖。

做法：判断写进 SQL

UPDATE users SET balance = balance - :amount
 WHERE user_id = :uid AND balance >= :amount;
-- rowcount = 0 → 400 INSUFFICIENT_BALANCE

加仓 ... AND quantity + :n <= 50；减仓 ... AND quantity > :n；清仓用 DELETE（写 0 违反 CHECK）。

实测（BUG-01 修复前）

两条连接各卖 2 股、实际只持 3 股：

卖出 4 股，余额 5000.00 → 5504.00，还剩 1 股

凭空多卖一股、多入账

修复后

并发两笔"卖 1" → [200, 400]，只入账一次；test_trades_concurrency.py 3 条守着。

不用 FOR UPDATE：SQLite 会静默忽略，本地绿、线上未必。

06 定价：一条价格是怎么来的

P(t+1) = max( floor , P(t) × (1 + α·S(t) + β·D(t)) )
S(t)   = clamp( z(t) / 3 , -1 , +1 )
z      = 本轮得分相对近 5 场均值的 z-score
参数值含义
α0.15满格 S=±1 → 单次 ±15%
β0需求项（本期不用）
floor1.0价格下限
clamp±20%单次涨跌对称上限
满格3σ1σ 记 1/3，避免二值跳动

真实一次调价（第 9 轮）

ZywOo：得分 81.3，近 5 场均分约 97 → S = −0.92

126.27 × (1 + 0.15 × −0.92) ≈ 108.75（−13.88%）；满格只有 ±15%，clamp 未触发

本场表现下滑（本轮得分 81.3，S=-0.92），价格下跌 13.88%

同一轮对照（页面可点）

flameZ 79.9 分 → S=+1.00，64.74 → 74.45（+15.00%）：分数更低反而涨

价格比的是「和自己近 5 场比」；两个详情页折线最后一点点开即是这两条（4 条测试守着 reason 契约）。

07 定价的诚实部分：它会长期温和下行

100 seed × 30 轮

指标结果
区间收益中位数 −7.40%，均值 −6.46%
方向一致率99.99%（涨跌接近 1:1，公式无偏）
单次最大变动≤ 15.01%，clamp 触发 0 次
≥4 人盈利的 seed17%

根因：① 得分在 100 处截断，高分段右尾削平 → E[S] 略小于 0；② 乘性更新的波动拖累。

不是 bug 是机制特性；α 调小可收敛（报告有 α=0.15/0.08/0.05 对比）。

智能体回测（seed 42 / 20 轮）

策略收益率最大回撤
规则版 AI−3.52%5.90%
随机−0.59%2.59%
买入持有−10.78%14.88%

结论只说一条：规则版 AI 回撤明显低于买入持有（3 seed 中 2 次跑赢收益），但 20 轮样本不能宣称"稳定跑赢"。

LLM 版回测待有密钥后补跑（已在报告如实标注）。

08 AI 智能体：只给建议，永不改余额

固定 6 字段契约

{
  "player_id": 1,
  "action": "HOLD",
  "reason": "近 5 个价格点累计变动 +25.5%…",
  "risk_level": "LOW",
  "source": "rule_fallback",
  "disclaimer": "仅为分析建议，不构成投资建议…"
}

降级是设计的一部分

无密钥 / 超时（20s）/ 非 JSON / 枚举非法 → 一律 HTTP 200 + rule_fallback，绝不 4xx/5xx 阻塞交易。

四层测试守住它

  • test_llm_agent.py 13 条：注入假 client，不碰网络
  • test_ai_fallback.py 6 条：阈值规则
  • test_api_ai.py 7 条：契约 / 只读 / 降级
  • e2e：调用前后余额与持仓完全不变

规则版与 LLM 同源可解释：LLM 是增量，不是命门。
