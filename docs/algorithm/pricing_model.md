## 2. 核心公式（方案 A）

```
P(t+1) = max( P_floor , P(t) × (1 + α × S(t) + β × D(t)) )

其中：
  S(t) = clamp( z-score(近 N 局表现分) , -1 , +1 )
  D(t) = 该选手净买入量 / 该选手总成交量     ∈ [-1, +1]
  z-score = (x - mean(最近 N 局)) / std(最近 N 局)   （std=0 时取 0）
```

## 3. 参数含义与取值

| 参数 | 符号 | 默认值 | 含义 | 调大后果 | 调小后果 | 配置位置 |
| --- | --- | --- | --- | --- | --- | --- |
| 表现权重 | α | 0.15 | 比赛表现对价格的影响强度 | 价格剧烈波动，像过山车 | 价格几乎不动，看不出机制 | `settings.pricing_alpha` / `.env` |
| 需求权重 | β | 0.0（初版） | 市场买盘对价格的影响 | 容易被单笔大单操纵 | 需求因子形同虚设 | `settings.pricing_beta` |
| 价格下限 | floor | 1.0 | 防止归零/为负 | 底部失真 | 可能跌到 0 | `settings.pricing_floor` |
| 滚动窗口 | N | 5 | 用最近几局算表现信号 | 反应迟钝 | 噪声大、抖动 | `pricing.standardize_score(window=5)` |
| 单次最大涨幅 | clamp | ⬜ 待定（建议 ±20%） | 防止极端数据拉爆价格 | 保护不足 | 机制失效 | `pricing.py` 内常量 |

## 4. 输入 / 输出约定（与 B 的接口）

| 项 | 内容 |
| --- | --- |
| 输入 | `current_price: float`、`score_delta: float`、`demand_signal: float` |
| 输出 | `PriceUpdate(new_price, change_pct, reason)` |
| 精度 | 价格与涨跌幅保留 2 位小数 |
| 异常 | `current_price <= 0` → `ValueError` |
| 落库 | 由 B 写入 `price_history(player_id, price, reason, ts)`，C 不直接操作数据库 |

## 5. 可解释性：reason 怎么生成

`reason` 是给用户看的中文短句，必须能对应到公式里的某一项：

| 触发条件 | reason 示例 |
| --- | --- |
| S(t) > 0.3 | `模拟比赛表现提升（近 3 场均分 88，S=+0.42）` |
| S(t) < -0.3 | `近期比赛表现下滑（近 3 场均分 61，S=-0.55）` |
| D(t) 显著且 β>0 | `买盘集中，净买入占比 62%` |
| 触及 floor | `已触及价格下限，停止下跌` |
| 数据缺失 | `本场数据缺失，价格维持不变` |
