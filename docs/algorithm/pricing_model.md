## 0. 数据口径（第 1 天 7 个决策之一）

- 选手**身份真实**（公开的 CS2 职业选手），**价格与 `rating` 全部是项目模拟值**；
- `rating` = 项目模拟评分（0–100），**不是 HLTV Rating**，UI 展示必须标注"模拟"；
- 种子数据不含任何官方统计字段（`hltv_rating` / `kast` / `adr` 一律不用）；
- 成交价一律以 `players.current_price` 为准，时间统一 ISO 8601 UTC。

## 1. 方案选择

课程方案给了三档，本项目**默认 A 档保底**，B/C 为加分项：

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| **A（默认实现）** | 滚动窗口加权：价格 = 表现项 + 需求项 | 完全可解释，每条变动可归因，6 天内可完成 |
| B（加分） | 表现—市场融合模型 + 交互项 γ | 答辩叙事强，但需要更多数据与调参时间 |
| C（彩蛋） | LMSR 自动做市商 | 机制设计深度，非必需 |

> ✅ 决策：**只保证 A 跑通**。B/C 若实现，必须作为 A 的插件（`update_price` 之外单独函数），不得替换 A。

## 2. 核心公式（方案 A）

```
P(t+1) = max( P_floor , P(t) × (1 + α × S(t) + β × D(t)) )

其中：
  z(t)   = (x - mean(最近 N 场)) / std(最近 N 场)        （std = 0 时取 0）
  S(t)   = clamp( z(t) / Z_FULL_SCALE , -1 , +1 )          （Z_FULL_SCALE 默认 3.0，3σ 记"满格"）
  D(t)   = 该选手净买入量 / 该选手总成交量                  ∈ [-1, +1]
```

**两条护栏**

1. `MAX_STEP_PCT = ±20%`：**对称 clamp**，单次涨跌都最多 20%（超出部分按上限执行，`reason` 会写明）。
2. `floor = 1.0`：clamp 之后若仍低于下限（α 被调大、价格本就很低），停在 1.0，`reason` 写"已触及价格下限"。

> **为什么是 `z/3` 而不是 `clamp(z,-1,1)`**：直接用 z 时 1σ 就记满格（约占 32% 场次），
> 实测大部分场次都顶到 ±15%，价格失去层次。改成 3σ 满格后：1σ ≈ ±5%、2σ ≈ ±10%，
> 只有真正的爆发/崩盘才满格。α 的语义也随之固定：**α × S，S∈[-1,1]，满格 = ±15%**。
> 若评审要求字面口径，把 `Z_FULL_SCALE` 设为 `1.0` 即可（等价于 `clamp(z,-1,1)`）。

## 3. 参数含义与取值

| 参数 | 符号 | 默认值 | 含义 | 调大后果 | 调小后果 | 配置位置 |
| --- | --- | --- | --- | --- | --- | --- |
| 表现权重 | α | **0.15** | 比赛表现对价格的影响强度 | 价格剧烈波动，像过山车 | 价格几乎不动，看不出机制 | `settings.pricing_alpha` / `.env` 的 `PRICING_ALPHA` |
| 需求权重 | β | **0.0**（初版） | 市场买盘对价格的影响 | 容易被单笔大单操纵 | 需求因子形同虚设 | `settings.pricing_beta` / `PRICING_BETA` |
| 价格下限 | floor | **1.0** | 防止归零/为负 | 底部失真 | 可能跌到 0 | `settings.pricing_floor` / `PRICING_FLOOR` |
| 滚动窗口 | N | **5** | 用最近几场算表现信号 | 反应迟钝 | 噪声大、抖动 | `standardize_score(window=5)` |
| 单次变动上限 | clamp | **±20%**（已定稿，写死） | 防止极端数据一次把价格拉爆 | 上涨/下跌更猛，演示风险高 | 保护不足 | 常量 `MAX_STEP_PCT` |
| 满格 σ 数 | Z_FULL_SCALE | **3.0** | 几倍标准差记 S=±1 | 更敏感（1σ 就满格） | 更迟钝 | 常量 `Z_FULL_SCALE` |

参数优先级：**显式传参 > `settings` > 环境变量 > 模块常量**。

## 4. 输入 / 输出约定（与 B 的接口）

| 项 | 内容 |
| --- | --- |
| 函数 | `update_price(current_price, score_delta, demand_signal=0.0, *, alpha=None, beta=None, floor=None) -> PriceUpdate` |
| 输入 | `current_price: float`、`score_delta: float`（S(t)，先用 `standardize_score()` 算）、`demand_signal: float`（D(t)，初版 0.0） |
| 输出 | `PriceUpdate(new_price, change_pct, reason, old_price, signal, step_pct, capped, floored)` |
| 精度 | 价格与涨跌幅保留 2 位；`change_pct` 由取整后新价反算，保证「价格 ×（1+涨跌幅）」自洽 |
| 异常 | `current_price <= 0`、非有限数值、`alpha/beta < 0`、`floor <= 0` → `ValueError` |
| 落库 | 由 B 写入 `price_history(player_id, price, prev_price, change_pct, reason, ts)`，C 不直接操作数据库 |

## 5. 可解释性：reason 怎么生成

`reason` 是给用户看的中文短句，必须能对应到公式里的某一项（均为真实输出）。

**第 4 天起 reason 带上"本轮得分"**（`update_price(..., score=...)`）：`price_history.reason` 因此能直接
追溯到是哪一场表现算出来的。用词固定为"**得分**"——B 的 `with_score_in_reason()` 以它为幂等标记，
命中就不再追加，避免"C 拼一次、B 再拼一次"的双写；不传 `score` 时保持旧文案，由 B 的那层兜底补上。

| 触发条件 | reason 示例（传 score=88.0 时） |
| --- | --- |
| S(t) > 0.3 | `本场表现提升（本轮得分 88.0，S=+0.82），价格上涨 12.35%` |
| S(t) < -0.3 | `本场表现下滑（本轮得分 62.5，S=-0.81），价格下跌 12.18%` |
| S(t) ∈ [−0.3, 0.3] | `表现与近期均值接近（本轮得分 80.0，S=-0.07），价格下跌 1.00%` |
| 无历史（第 1 场） | `表现与近期均值接近（本轮得分 80.0，S=+0.00），价格维持不变` |
| 触发 ±20% 上限 | `本场表现提升（本轮得分 95.0，S=+1.00），单次变动超过 ±20% 上限，已按上限执行，价格上涨 20.00%` |
| 触及 floor | `本场表现下滑（本轮得分 40.0，S=-1.00），已触及价格下限，停止下跌，价格下跌 15.00%` |
| D(t) 显著且 β>0 | `本场表现提升（本轮得分 88.0，S=+0.60），买盘集中，净买入占比 62%，价格上涨 9.30%` |

### 7.2 100 seed 稳定性（seed = 1…100，每个 seed 30 轮）

| 指标 | 结果 |
| --- | --- |
| 区间收益（每 seed 内 7 名参与者的平均） | 中位数 **−7.40%**，均值 **−6.46%**，范围 −20.82% ~ +12.20% |
| 每 seed 盈利选手数 | 中位数 **2 人**（0–6 人）；≥4 人盈利的 seed 占 **17%** |
| 平均单次变动幅度 | 中位数 **5.68%**（范围 5.26%–6.12%） |
| 单次最大变动 | 全部 ≤ **15.01%**，clamp / floor 触发 **0 次** |
| 方向一致率 | 最低 **99.52%**，平均 **99.99%** |

**结论与已知风险（答辩口径要带上）**

1. 机制本身是"跟相对预期走"：方向一致率≈100%，涨跌次数接近 1:1，**公式没有人为偏向**。
2. 但 100 seed 的区间收益中位数是 **−7.4%**，说明价格存在**温和的长期下行**。根因是两件事叠加：
   - **得分在 100 处被截断**：8 人里 5 人 base rating ≥ 80，模拟得分约 **2.5%** 的场次顶到 100，正态右尾被削平 → `S` 的期望略小于 0，价格因此缓慢下移；
   - **乘性更新的波动拖累**：即使 `E[S]=0`，`E[log P]` 也会因方差而下降。
3. 两者都与 α 成正比，实测调小 α 后下行明显收敛：

   | α | 区间收益中位数 | 平均单次幅度 |
   | ---: | ---: | ---: |
   | 0.15（当前默认） | −7.64% | 5.69% |
   | 0.08 | −2.27% | 3.03% |
   | 0.05 | −0.96% | 1.90% |

4. 第 5 天可选的三种修法（按改动代价排序）：
   - ① 演示用 **α=0.08**：波动与下行都更温和，无需改代码；
   - ② 让模拟得分的标准差随 base 收缩（`σ = min(7, (100 - base) / 2.5)`），使 3σ 不触顶，从源头去掉负偏；
   - ③ 价格加一层均值回归（每轮向初始价回拉约 1%）。
5. **本次不改代码**：改动会影响第 2/3 天已验收的 8 条演示输出与 §8 案例数字，留到第 5 天统一决策。
