# 非功能需求（Non-Functional Requirements）

> **负责人**：D 牵头，B 负责性能与可靠性条目 ｜ **截止**：第 2 天结束 ｜ **状态**：✅ 已填写（第 4–5 天填实测值）
> **对应课程指标**：#7 可靠性、性能、可用性；#20 隐私与数据安全

> ⚠️ 课程明确要求：非功能需求必须**可测量**。禁止写"界面要好看""速度要快"，
> 必须写"首屏加载 ≤ 3s""单接口 P95 ≤ 300ms"这种。

## 1. 性能（Performance）

| 编号 | 指标 | 目标值 | 测量方法 | 状态 |
| --- | --- | --- | --- | --- |
| NFR-P-01 | 行情列表接口响应 | 本地 P95 ≤ 300ms（8 名选手） | 真实 uvicorn + 20 次采样 P95 | ✅ 24.17ms（2026-10-24 实测） |
| NFR-P-02 | 买入/卖出接口响应 | P95 ≤ 500ms | 同上 | ✅ 买 36.24ms / 卖 28.86ms（P95） |
| NFR-P-03 | AI 分析接口响应 | 正常 ≤ 8s；超时上限 20s 后必定返回 | 计时 + 掐断模型 | ✅ 25.15ms（rule_fallback；有密钥的 LLM 待第 5 天线上） |
| NFR-P-04 | 前端首屏（本地） | ≤ 3s（含 8 名选手行情） | 浏览器 Performance 面板 | 🟡 待第 5 天浏览器实测 |
| NFR-P-05 | 价格历史图渲染 | ≥ 100 个点不卡顿 | 手动滚动/交互 | 🟡 待第 5/6 天浏览器实测 |

## 2. 可靠性（Reliability）

| 编号 | 指标 | 目标值 | 说明 |
| --- | --- | --- | --- |
| NFR-R-01 | 交易原子性 | 余额/持仓/流水三者要么全成功要么全回滚 | 事务保证，失败用例必测 |
| NFR-R-02 | AI 故障隔离 | 模型不可用时交易/定价/行情 100% 可用 | 降级到 rule_fallback |
| NFR-R-03 | 数据持久化 | 后端重启后历史交易与持仓不丢失 | 线上需配置持久化磁盘或 PostgreSQL |
| NFR-R-04 | 错误可读性 | 所有 4xx 返回中文 `message`，前端可直接展示 | 不用裸 500 |

## 3. 并发与一致性（Concurrency）

| 编号 | 指标 | 目标值 | 说明 |
| --- | --- | --- | --- |
| NFR-C-01 | 并发下单 | 同一用户并发买入不得出现"余额变负"或"重复扣款" | 事务 + 行级校验（SQLite 下用写锁/串行化） |
| NFR-C-02 | 超卖防护 | 持仓不足时卖出必须失败 | 校验在最靠近写入的位置执行 |
| NFR-C-03 | 持仓上限 | 任意时刻单选手持仓 ≤ 50 股 | 校验含本次交易后的总量 |

## 4. 可用性（Usability）

| 编号 | 指标 |
| --- | --- |
| NFR-U-01 | 交易成功/失败都有明确反馈（颜色 + 文案），不出现"点了没反应" |
| NFR-U-02 | 加载中、无数据、请求失败三种状态都有兜底 UI |
| NFR-U-03 | 金额统一保留 2 位小数，涨跌带正负号与颜色 |

## 5. 安全与隐私（Security & Privacy）

| 编号 | 指标 |
| --- | --- |
| NFR-S-01 | LLM API 密钥只存在后端环境变量，不下发前端、不进 Git |
| NFR-S-02 | `.env`、`*.db` 不提交仓库（见 `.gitignore`） |
| NFR-S-03 | 仅使用公开可查的选手职业身份信息（姓名/战队/位置），不使用隐私数据；价格与评分为项目模拟值，且全站声明非官方、无关联 |
| NFR-S-04 | 部署后仅开放必要 CORS 来源，不使用 `allow_origins=["*"]` |

## 6. 可维护性与可复现（Maintainability & Reproducibility）

| 编号 | 指标 |
| --- | --- |
| NFR-M-01 | 新人按 README 可在 20 分钟内本地跑起来 |
| NFR-M-02 | 依赖锁定：`requirements.lock.txt` + `package-lock.json` 入库 |
| NFR-M-03 | 演示数据固定（`data/seed_players.json` + 固定 seed），每次演示可复现 |
| NFR-M-04 | 接口契约变更必须同步 `docs/software/api_contract.md` 并通知对接人 |
| NFR-M-05 | CI 通过才允许合并到 main |
