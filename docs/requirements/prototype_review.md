## 2. 三层模型核对## 2. 三层模型核对

### 2.1 用户任务与场景 ✅

| 证据 | 说明 |
| --- | --- |
| `docs/requirements/problem_definition.md` | 5W1H + 真实约束（6 天、四人、无真实赛事接口） |
| `docs/requirements/user_stories.md` | **7 条 INVEST 用户故事**，每条第 1–3 条验收条件（AC） |
| `README.md` §一句话介绍 / §合规声明 | 面向"想低成本体验选手行情、但不愿碰真钱"的用户 |

主任务流（全局唯一）：**看行情 → 进详情看走势与 AI 建议 → 买入 → 看持仓 → 卖出 → 看流水**。所有页面围绕这一条链路，没有第二套入口。

### 2.2 界面设计（结构·组件·流程）✅

| 维度 | 现状 | 证据 |
| --- | --- | --- |
| 信息架构：哪些信息放哪一区 | 4 条路由：`/` 市场、`/players/:id` 详情、`/positions` 持仓、`/trades` 流水；每页"数据区 + 操作区 + 状态区"三段式 | `wireframes/README.md` §1 Mermaid、`src/router/index.ts` |
| 布局 | 顶部固定导航（品牌 / 市场 / 持仓 / 流水 / 连接徽标 / 余额）+ 主内容区（单列，最大宽度约束）+ 页脚合规声明 | `src/App.vue` |
| 组件 | `TradePanel`（数量 + 买入/卖出）、`PriceChart`（SVG 折线 + tooltip + 明细列表）、`LoadingState` / `EmptyState` / `ErrorState` | `src/components/` |
| 流程 | 交易成功后 `refreshAccount()` 局部刷新余额/持仓/流水，不整页重载（`silent=true` 分支保输入不丢） | `PlayerDetailView.vue::loadCore` |
| 状态：空 / 加载 / 成功 / 拦截 / 出错 | 5 态齐备并已截图：加载 `12`、空 `13`、失败 `14`、5 条错误分支 `07~11`、成功 `03/05` | `evidence/` |

### 2.3 视觉设计（色彩·字体·间距）🟡

详见 **§3 视觉设计规范**。一句话：**色彩已完全 token 化且对比度达标，字体/间距/圆角仍是散落硬编码，且无设计规范文档**（本文档 §3 即为补齐）。

### 2.4 用户体验（反馈·容错·信任）🟡

详见 **§4 检查清单**。已具备：三态 + 中文错误直出 + 可重试 + AI 免责声明 + 来源徽标。缺口集中在 **响应式、无障碍、等待可感知、防错二次确认**。
