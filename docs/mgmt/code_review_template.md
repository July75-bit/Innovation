# 代码评审模板（PlayerStock 版）

> **负责人**：D ｜ **依据**：ACMWDevHubPPT `Methodology/CodeReviewTemplate.md`（改编）｜ **配套**：`.vscode/settings.json`、`pyproject.toml` 的 `[tool.ruff.lint]`、CI 三 job
> **怎么用**：复制本文件为 `docs/reviews/YYYY-MM-DD_<模块>_<作者>.md` 再填写；**只填事实**（是 / 否 / 不适用 / 具体名称），不写"应该、大概、感觉"。
> **结论三态接 Kanban**：代码质量良好 → 卡片拖 `Done`；存在问题 → 回 `In progress` 并登记 `BUG-xx`；需重新审查 → 复查后在 §6 记录。

## 0. 评审注意事项

- **建议时长：1.5–2 小时**（超过说明这段改动太大，应拆分）。
- **什么改动必须走本模板**（三选一命中即走）：
  1. 改动 **> 100 行**；
  2. 触碰 **交易事务 / 定价公式 / AI 契约字段 / 数据库表结构**；
  3. 修的是 **P0/P1 缺陷**。
  其他小改动（文案、样式、注释）走"双人 quick check"即可，不必填表。
- **评审对象**：业务流程复杂、有技术难度、耗费资源多、或由新手写的代码（原模板的说法，我们对事不对人）。
- **评审前作者必须先自测**：`python -m pytest`（应 120 passed）+ `ruff check` 本地全绿，否则打回。
- **谁审谁（不能自审）**：按写权限**交叉**分配 —— A 的 `code/frontend/` 由 B 或 D 审；B 的后端由 C 或 D 审；C 的 `core_engine/` 由 B 审；D 的 `ai/`、`tests/` 由 A 或 C 审。
