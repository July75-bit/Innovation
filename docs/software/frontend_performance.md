# 前端加载性能优化（2026-11-19）

> 触发：用户反馈「切换页面、点开二级页面总要加载几秒钟」。
> 方法：先定位"慢在哪"（CDP 网络瀑布 + 人为延迟），再逐项改；所有对比都在**同一模拟网络**下跑
> baseline（优化前 worktree）与 patched（优化后）两份**生产构建**。

## 1. 诊断方法与模拟条件

- 用 `vite preview` 起两份构建（优化前 / 优化后），同一后端、同一套种子数据。
- CDP `Fetch` 拦截所有 `/api/*` 人为加 **200ms 网络延迟**（模拟真实 RTT），
  并给 AI 三个接口额外 **1200ms**（模拟 DeepSeek 单次 2–5s 中的一段）。
- 用 `requestAnimationFrame` 轮询测量"目标元素出现的时间"；用页面级 fetch 计数器数请求次数。

## 2. 根因（按影响排序）

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | 详情页 AI 三个接口 **串行**：`analysis → decision → narrative`（每个都走 LLM） | 第 2 块要等第 1 块、第 3 块再等第 2 块：总等待 = 三者之和 |
| 2 | 每个页面挂载都重新请求同一份 GET；来回切页重复等待 | 二次进入详情/来回切"持仓"都在等网络 |
| 3 | 点卡片才开始下载详情页分包 + 拉数据 | 点击到首屏之间的空窗 |
| 4 | 详情页 header 的 `Promise.all` 里混入 `positions`（只影响交易面板提示） | 持仓接口慢时，整页首屏被拖住 |
| 5 | 后端 Render 免费实例冷启动（30–60s） | 前端无法完全解决，靠 cron 巡检/预热兜底（既有 `agent_patrol`） |

## 3. 改动

- **GET 内存缓存**（`src/api/cache.ts`）：
  - `listPlayers/account/positions/trades` 30s；`player/prices` 120s；AI 结果 120s；
  - 同一 key **并发合并**（详情页双挂载不会重复打）；
  - 失败不缓存；
  - **失效**：买/卖成功后整体失效；页面「刷新」按钮失效；「重新分析」只失效该选手的 analysis；
  - 不落 localStorage（数据时效性优先，内存缓存解决"来回切"）。
- **AI 三个请求并行**：`Promise.allSettled`；`analysisLoading` 只跟"建议文本"绑定，决策/叙事晚到再补，
  互不阻塞（建议一出现就不再转圈）。
- **悬停/聚焦/按下预取**：市场卡片 `mouseenter/focus/pointerdown` 时预下载详情页分包 +
  预取该选手详情/价格/持仓，点进去直接用。
- **空闲预取路由分包**：首屏稳定后 `requestIdleCallback` 预取详情/持仓/流水/赛程的 JS/CSS。
- **连接预热**：`main.ts` 启动即对 `VITE_API_BASE_URL` 插 `preconnect` / `dns-prefetch`。
- **详情页 header 不等持仓**：详情+价格并行出首屏，持仓单独补（先按 0 显示，交易最大可买由后端兜底）。

## 4. 实测对比（200ms RTT + AI 每请求 +1200ms）

| 场景 | 优化前 | 优化后 | 变化 |
| --- | --- | --- | --- |
| 详情页 · 决策卡出现 | 3200 ms | 1773 ms | **-1.4s** |
| 详情页 · 叙事出现 | 4600 ms | 1773 ms | **-2.8s** |
| 二次进入同一选手 · 首屏 | 381 ms（7 个 API 请求） | 163 ms（1 个 health） | **-218ms**，请求 7→1 |
| 二次进入同一选手 · AI 建议 | 1780 ms | 164 ms | **-1.6s** |
| 悬停 600ms 再点开 · 首屏 | 362 ms | 145 ms | **-217ms** |
| 重复切「持仓」 | 268 ms（3 个请求） | 51 ms（1 个 health） | **-217ms**，请求 3→1 |

> AI 并行收益与单次 LLM 耗时成正比：线上 DeepSeek 单次 2–5s 时，后两块最多可提前 2×单次耗时。

## 5. 风险与边界

- **数据新鲜度**：缓存 TTL 30–120s；交易成功/点刷新/重新分析都会失效，不会出现"买完余额还是旧值"。
- **mock 模式**（`VITE_USE_MOCK`）不走缓存，避免测试/演示时看到 mock 之外的脏数据。
- **browser 内存缓存**：页面整页刷新后清空；这是刻意取舍，避免长期陈旧。
- **后端冷启动**（Render 免费）：前端只能通过预取/预热减少体感；答辩前仍要 `bootstrap + prewarm`。

## 6. 后续可做（未做）

- AI 接口改为**流式**（SSE/分块）把"等 2–5s"变成"逐字出现"。
- 后端给 GET 加 `Cache-Control`/ETag，让浏览器/网关也能复用。
- Service Worker 预缓存静态资源（当前离线演示需求不强，暂不做）。
- 详情页首屏骨架（目前是整页 spinner → 可拆成 header 骨架 + 图表骨架）。
