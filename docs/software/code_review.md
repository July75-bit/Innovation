## 1. 什么时候必须评审（触发门槛，三选一）

1. 改动 **> 100 行**；
2. 触碰 **交易事务 / 定价公式 / AI 契约字段 / 表结构**；
3. 修 **P0 / P1 缺陷**。

## 2. 怎么审（顺序不能反）

| 步骤 | 做什么 | 判据 |
| --- | --- | --- |
| 1 | **机器先过** | `pytest` 全绿（320 条）+ `ruff` 四条门槛 + 前端 `lint/build` |
| 2 | **人看事实** | 提交说明里的每个数字/断言，逐条到仓库里核对（不信作者自述） |
| 3 | **人看设计** | 四类总体意见：可读性 / 正确性 / 边界与失败处理 / 可测试性 |
| 4 | **给三态结论** | 通过 / 存在问题（回 In progress + 登记 BUG-xx）/ 需重写 |
| 5 | **落到看板** | 通过 → Kanban 的 Done；有问题 → In progress + Issue |
