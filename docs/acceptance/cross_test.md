### 3.2 最严重的 3 个体验问题（原文摘录）

| # | 现象（可验证的事实） | 影响的用户与场景 | 改进建议 | 对应题号 |
| --- | --- | --- | --- | --- |
| 1 | 打开就是 API 配置页，新用户先看到门槛，不是产品价值 | 第一次来的写作者，还没试就被劝退 | 首屏先给示例作品或直接试写，配 Key 推迟到第一次生成 | P1、H2、H7 |
| 2 | 点「创建作品」后不直接进作品，先弹文风与 Skill 设置，再点一次才生成 | 想开始写的人被多打断一步，设置也重复出现 | 创建后直接进作品页；文风与 Skill 收在前一屏，可选、默认跳过 | H7、H8 |
| 3 | 简单试写后，生成内容有明显与现实不符的部分 | 写作者得逐段核查，信任成本高 | 事实性内容标「AI 生成，未核实」，关键设定可回看，减少编造 | A3、A11 |

### 3.3 对方整体结论（原文）

> 整体能看出是个写作工具，但第一次用不太顺：打开先要配 API Key，点「创建作品」之后又被文风与 Skill 设置打断一次，
> 真正开始写要绕几步。简单试写下来，生成内容有部分和现实对不上，界面偶尔还会崩，用得比较吃力。
> 33 项里通过 9、部分通过 17、不通过 6、未覆盖 1。短板主要在体验层：门槛、流程顺序、内容可信度；
> 界面分区和视觉层级还算扎实，是可以继续打磨的地方。

### 3.4 测试自评（原文要点）

- 最有把握：**P1 与 H2**（「先看到配置页」在首页、设置、费用确认三处反复出现，可重复验证）；
- 最没把握：**P4**（推荐分 7/10 是主观印象，没有真实外部用户样本）；
- 未测到：**A9**（灰度 / 色觉 / 对比度本轮没有实测，故判「未覆盖」而不是「通过」）。

### 3.5 本次测试的缺口（如实记录）

- 原表 §7「实测记录」的 S01–S08 截图登记**未填写**，本轮没有保存对方界面的截图；文字证据以每题「现象与证据」栏为准。
- 只测了**一个**外部组（Tome），样本量小；结论仅代表本组 4 人的一次实测，不外推为通用结论。

### 4.4 引用时必须带上的口径

- 对方表中明确写「**本表未重新进行测试**」，且「现象与证据」多处引用「资料1/资料2」——
  **更接近材料评审，而不是完全独立的重测**；答辩时说「他组评审（2026-11-14）」，不要说「他组独立实测」。
- 对方同样把 **A9（灰度/色觉）判为「未覆盖」**——但需说明：**我方自己的 A9 已做**（灰度 + WCAG 实算：深色正文 14.33:1、玻璃最低 8.55:1，12 个「路由×主题」组合自动审计 0 违规，见 `tests/playerstock_agent_demo_user_test.md` A9 行）；「未覆盖」只是对方这一轮没做，不代表产品没验证。
