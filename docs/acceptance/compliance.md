### 4.1 接口暴露面与跨域（CORS）口径 —— 第 5 天 B 的决策

| 项 | 口径 |
| --- | --- |
| 是否用 `allow_origins=["*"]` | **设计上不用**（`nonfunctional_spec.md` NFR-S-04）。线上放行来源由 `CORS_ORIGINS` 环境变量决定，代码按白名单下发 |
| 具体规则 | ① 配了具体域名 → 只放行这些来源；② 显式写 `*` → 放行全部并在启动日志 WARNING；③ **没配** → 退化为 `*` 并 WARNING（宁可在日志里被看见，也不要让演示环境静默白屏） |
| 为什么允许"没配时退化" | 这是运维兜底而非设计默认：`*` 会让"配置漏填"变成无声事故。退化 + 告警让问题出现在日志第一屏，答辩前能发现并补 `CORS_ORIGINS` |
| 接口本身有无鉴权 | 无登录、无 Cookie、无会话；`GET` 是公开演示数据，`POST /api/trades/*` 作用于**单一共享演示账户**。因此 CORS 在这里不是访问控制手段（浏览器跨域限制本就不防直连） |
| 敏感信息 | 不回传密钥、不回传数据库连接串；`/api/analysis` 只回建议文本与 `source` 字段 |
| 可验证性 | `tests/unit/test_cors_config.py` 4 条用例钉住三种分支；本机实测：配 `https://frontend.example.com` 时陌生来源拿不到 `access-control-allow-origin`，未配置时为 `*` 且日志告警 |

### 4.3 账号口令与令牌的处理口径（第 7 轮新增）

| 数据 | 存哪 | 怎么保护 |
| --- | --- | --- |
| 口令 | **不存明文** | PBKDF2-HMAC-SHA256，随机盐，迭代 100,000 次；只存 `算法$迭代$盐$散列` |
| 令牌 | `auth_tokens` 表 | 随机不透明串（`secrets`），有效期 30 天，退出/删号即删记录 |
| 日志 | `logs/app.log` | 只记 user_id 与昵称，**从不记口令与令牌**（代码中无此类调用） |
| 浏览器 | localStorage | 仅存令牌与用户名；清除浏览器数据即失效 |

> 说明：这是课程作品的最小可用账号体系，**没有**找回密码 / 邮箱验证 / 频次限制加固，
> 已列入已知限制；生产化前需补：登录失败限流、口令强度策略、HTTPS 强制。
